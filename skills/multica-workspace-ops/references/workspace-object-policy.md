# the workspace Object Policy

the workspace moves work through:

```text
idea → validation → offer → outreach → sale → delivery → proof → repeat
```

Use the lightest useful Multica object:

1. Issue — default concrete work unit
2. Project — durable business, delivery, product, or operations lane
3. Agent — recurring execution role
4. Squad — coordinated multi-agent routing
5. Autopilot — recurring safe automation

## Projects

Create a project when several of these are true:

- clear buyer, user, or operational owner
- multiple issues are expected
- work lasts longer than a short task
- repository or deployed product exists
- revenue, delivery, or operations are materially affected
- recurring follow-up or a human partner is involved

Otherwise, create an issue in a suitable existing project.

## Issues

Issues should describe a concrete next action and include context, goal, inputs, scope, acceptance criteria, and approval rules. Prefer issues over creating new structural objects.

## Agents and squads

Create agents only for repeated roles. Create squads only when a leader must route work across several recurring roles. Both require explicit approval unless the user already requested that exact structure.

## Autopilots

Use autopilots for recurring checks or issue creation. Prefer outputs that a human can review.

Suitable examples:

- blocker review
- lead-research queue
- active-project summary
- continue/kill review
- runtime health check

Do not autonomously send outreach, publish, set prices, spend money, alter auth/configuration, or delete/archive objects.

## Human partners

Capture role, skills, availability, decision authority, ownership, and approval boundaries. Do not commit private personal or customer details to the skill repository.
